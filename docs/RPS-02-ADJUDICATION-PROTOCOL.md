# RPS-02 — Protocole d’adjudication v1.0

## Principe

L’adjudication intervient uniquement après deux annotations indépendantes.

Elle ne modifie ni l’annotation A ni l’annotation B.

## Pour chaque désaccord

Documenter :

- `blindImageId`
- dimension concernée ;
- valeur A ;
- valeur B ;
- caractère réellement observable ou non ;
- décision : A / B / autre valeur / unknown / not_assessable ;
- justification courte ;
- personne ayant arbitré ;
- date ;
- besoin éventuel d’une revue méthodologique.

## Règle

Si l’image ne permet pas de trancher proprement, l’issue correcte peut être `unknown` ou `not_assessable`.

Il est interdit de choisir une valeur simplement parce qu’elle correspond mieux à une notation de la méthode source.

## Séparation

L’adjudication ne produit pas automatiquement :

- un statut de fertilité ;
- un statut d’ovulation ;
- un Peak ;
- un diagnostic ;
- un mapping RPS-02.

Le mapping RPS-02 fait l’objet d’une revue distincte.

## Rapport final

Le rapport doit présenter séparément :

1. annotations A ;
2. annotations B ;
3. désaccords ;
4. adjudications ;
5. décisions d’exclusion ;
6. limites ;
7. éventuelle proposition de mapping RPS-02.

Aucun accord final ne doit masquer les désaccords initiaux.
